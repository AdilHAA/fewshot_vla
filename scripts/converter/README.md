# Конвертация LIBERO

`convert_libero.py` удаляет no-op шаги и задаёт оставшейся последовательности 10 FPS.
HDF5 сохраняется в HDF5, LeRobot v3 — в LeRobot v3. Скрипт работает отдельно от репозитория.

## HDF5 LIBERO-Gen

Python 3.10+, CPU; симулятор и LeRobot не нужны.

```bash
python -m pip install numpy h5py
python scripts/converter/convert_libero.py \
  --input-format hdf5 \
  --source /data/gen_native256_v4 \
  --out /data/gen_10fps_filtered \
  --relative-actions --fps 20 --action-offset 0
```

Вход — один HDF5-эпизод или каталог с `preaction.hdf5`. Для других имён используйте
`--pattern '*.hdf5'`. На выходе сохраняются относительные пути к эпизодам.

Контракт входа:

- `actions`: `[T,7]`, исходные относительные OSC-команды в `[-1,1]`, до нормализации модели.
- `observation_state`: `[T,8]` — EEF xyz, axis-angle и два gripper qpos.
- Две RGB-камеры: `uint8 [T,256,256,3]`; определяются по форме или задаются через `--camera-keys`.
- Кадр и state строки `t` записаны **до** `actions[t]`, `action_offset=0`.
- FPS и offset из metadata должны совпадать с аргументами; аргументы заполняют отсутствующие значения.

Имена можно задать через `--actions-key`, `--state-key`, `--camera-keys`.
Дополнительные массивы по времени укажите в `--time-keys`, статические — в `--static-keys`.
Не помечайте массив статическим только ради обхода ошибки длины.

## No-op и время

Правило взято из [OpenVLA-OFT](https://github.com/moojink/openvla-oft/blob/main/experiments/robot/libero/regenerate_libero_dataset.py):
шаг удаляется при `norm(action[:6]) < 1e-4` и неизменной команде захвата относительно
последнего сохранённого действия. Начальные неподвижные шаги удаляются независимо от захвата.
Неподвижный шаг со сменой команды захвата сохраняется. Состояние фильтра сбрасывается на каждом эпизоде.

Все оставшиеся действия сохраняются без изменения значений, новые timestamps равны `i / 10`.
Это переназначение временной шкалы, а не физический пересчёт управления с 20 на 10 Гц.
Скрипт не выполняет replay и не проверяет успешность исполнения после удаления пауз.

## Подключение к загрузчику

Сначала обработайте один эпизод и прочитайте его своим загрузчиком. Проверьте
одинаковую длину камер/state/actions, `fps=10`, `action_offset=0` и соответствие выбранных строк.
Картинки HDF5 копируются без потерь и переворотов; кодировка захвата сохраняется.
Task ID и split не переназначаются. Полностью пустой после фильтрации эпизод вызывает ошибку.

В HDF5 группа `_conversion` хранит исходные индексы строк, FPS, timestamps и metadata.
Исходные индексы служат для связи с входной записью; для новой последовательности используйте
новую нумерацию строк и временную шкалу 10 FPS.
Внешние manifests/списки эпизодов и готовые кэши скрипт не переписывает.
Перед обучением подключите новый каталог в загрузчике и пересоберите зависящие от кадров кэши и статистики.

Исходник не меняется. Выходной каталог должен быть новым; незавершённая запись остаётся в `.partial`.

## Уже LeRobot v3

Python 3.12+; установите зависимости в отдельное окружение:

```bash
python -m pip install 'lerobot==0.5.1' 'av==15.1.0'
python scripts/converter/convert_libero.py \
  --input-format lerobot \
  --source /data/libero_20fps --out /data/libero_10fps_filtered \
  --relative-actions
```

Ожидаются Panda, `state[8]`, `action[7]`, захват `-1=open/+1=close`, две камеры 256×256.
По умолчанию камеры — `observation.images.image` и `observation.images.image2`;
для других имён используйте `--agent-camera` и `--wrist-camera`.
На выходе — AV1, 10 FPS, пересчитанные индексы, смещения видео и статистики;
task/episode ID и splits сохраняются, соответствие исходным строкам записывается в `conversion.json`.
